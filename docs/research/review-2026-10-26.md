# Adversarial review, 2026-10-26

Before the SMS webhook went public, 172 review agents read the foundation in six areas (webhook, brain,
validator and models, database, approvals, Code Mode sandbox). Each candidate finding then faced two or
three independent skeptics told to refute it, most with probes against the real code. A final reviewer
merged duplicates and ranked what survived.

- 76 candidate findings; 71 survived the skeptics; none stayed critical or high.
- 17 merged items: 7 medium, 10 low.

## Two live lessons

Two later live runs of Nemotron 3 Ultra were rejected by the hardened validator for wording, not numbers:
a lever named "Target Google ROAS" (a real bidding setting) and assumptions that said "the combined
effect of ads and email". Both rules were narrowed with the live wording as tests. A validator is only
as good as its false-positive rate on real model output, so every rule change is now checked live.

## Low findings still open

Clock handling between the database and the worker; approval codes stored in plain text in the inbound
table until the task ends; misleading wording on some refusals; one-plan printouts; brain file locking;
shared-record edge history; model input validation; remaining sandbox gaps (argument size, code
normalisation); test isolation. None affects the demo path; each is listed with its fix in the review
output.
